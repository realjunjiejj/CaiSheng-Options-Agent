# CaiSheng — Options Alpha Agents

## Strategy and AI logic

CaiSheng is an autonomous options agent built for a $100,000 Alpaca paper account. It scans confirmed after-market earnings and, during a fixed intraday window, the liquid ETF volatility universe `SPY/QQQ/IWM`. Its question is non-directional: will realized movement exceed or undershoot movement priced by executable option quotes? A LangGraph workflow runs an event-magnitude analyst and a quantitative volatility analyst, produces long- and short-volatility theses, and sends both to an independent model-risk critic. The deterministic selector may choose an ATM long straddle, a defined-risk short iron butterfly, or `NO_TRADE`. The option market's implied move is the forecast anchor; a strongly shrunk residual correction is applied only when point-in-time evidence exists. The reasoning roles can use structured language-model inference when a client is configured; otherwise they run deterministic synthesis. Every decision records the effective runtime and any fallback. Pricing, expected value, sizing, portfolio limits, and execution eligibility always remain deterministic.

Every run emits a hashed `caisheng.decision.v1` DecisionRecord containing point-in-time timestamps, explicit Alpaca stock/options feed labels, agent runtime and fallback evidence, implied and forecast move distributions, IV-crush estimate, candidate P&L/risk metrics, critic findings, rejection reasons, selected action, quantity, and mode (`live` or `replay_synthetic`). Competition mode explicitly requests IEX equities and the indicative options feed; the UI labels that limitation rather than implying OPRA/NBBO precision. Replay output is labelled synthetic and is never mixed with Alpaca paper P&L.

## Risk gates

The agent fails closed on missing provenance, stale/future/crossed/non-finite quotes, invalid option topology, inadequate liquidity, missing contracts, temporal leakage, out-of-distribution inputs, critic vetoes, a non-positive confidence-bound edge, or expected value below 2% of maximum loss. Competition gates use fresh broker equity and enforce: $250 target and $500 hard maximum loss per strategy, at most two open strategies, one new entry per day, 0.5% NAV total reserved risk, sufficient buying power, a $500 daily-loss halt, and a 1% high-water-mark drawdown halt. Entries stop during a halt; exact-contract risk-reducing closes remain eligible.

Autonomous entries additionally require a short-lived local authorization receipt. The mode-0600 receipt is HMAC-authenticated, bound to the verified paper account and exact hashed competition configuration, expires within eight hours, and contains no account identifier or credential. Changing a risk/execution setting, switching accounts, rotating the authentication key, tampering with the receipt, or reaching expiry blocks new submissions while preserving risk-reducing exit management. Arming never places an order.

Order plans are immutable and fingerprinted. SQLite enforces the legal lifecycle `PREVIEWED → APPROVED → INTENT_PERSISTED → SUBMITTING → broker state`, duplicate-exposure protection, one-time approval consumption, timeout reconciliation by the original client order ID, and append-only transition evidence. Partial fills remain monitored after canceling the unfilled remainder. A close requires broker-verified exact contracts and fresh quotes.

## Alpaca infrastructure and autonomy

CaiSheng uses Alpaca market data for underlying and option-chain snapshots and the Trading API for the authenticated $100,000 paper account, portfolio state, positions, orders, Level-3 multi-leg limit submission, cancellation, and reconciliation. Its Alpaca Technology Lockbox verifies the official agent-first Alpaca CLI against the exact paper endpoint, dynamically discovers and calls the official Alpaca MCP Server V2 under read-only `assets,options-data` toolsets, and fingerprints four installed official Alpaca agent skills. Lockbox is our proof method, not an Alpaca product. It emits no credentials or account identifiers.

CaiSheng's separate seven-tool FastMCP gateway exposes account, position, order, clock, quote, and option-chain reads plus guarded submission. Its write tool accepts only an already-approved canonical order token and persisted DecisionRecord ID; raw MCP order construction is rejected. Thus the official sponsor proof cannot trade, and every mutation still converges on one policy-enforced broker gateway. The CaiSheng CLI produces sanitized Lockbox, preflight, and reconciliation receipts. Account metadata binds the competition ledger to one paper account.

The lifecycle loop performs order reconciliation, exact-contract position monitoring, ETF/event scanning, LangGraph analysis, cross-candidate allocation, preview creation, lease-gated paper submission, exit management, and daily reconciliation. Repeated scanner runs are idempotent. The CLI provides `--competition-arm`, `--competition-disarm`, and `--competition-status`; the persistent-host schedule scans twice hourly from 10:20 through 14:50 ET and once in the AMC earnings window, but it never grants itself entry authority. The operator starts a time-bounded autonomous session, while disarming blocks new entries without interrupting monitoring or risk-reducing exits. The judge UI's first viewport displays live equity, realized P&L, reserved risk, circuit breaker, `AUTONOMY ARMED/DISARMED`, paper-only status, lease expiry, risk limits, frequency limit, universe, and scan window. **Agent** is sealed replay, **Paper Trade** owns fresh-data inspection, and **Evidence** reports broker-confirmed results separately from non-competition research evidence.

## Verification and competition output

The primary competition output is full-account Alpaca paper P&L against the immutable `$100,000` starting NAV. Governed closed-trade P&L is reported separately and requires both entry and exit broker IDs. Engineering verification currently passes all **347 repository tests**. The repository evidence receipt currently contains **0 governed broker-confirmed closed trades and $0 realized governed P&L**; judges should use the submitted Alpaca paper account ID and the live Command screen for the submission-time full-account result. The controlled replay result is **+$2,044 across four synthetic trades** and is labelled functional evidence—not a backtest, competition performance, or proof of predictive alpha. No real-money endpoint exists. Tests prove operational correctness—not future profitability. The system explicitly defers to implied move when a residual correction has not earned the right to override it.
